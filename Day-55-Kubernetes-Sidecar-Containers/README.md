# Day 55 - Kubernetes Sidecar Containers

## Challenge Overview

This is Day 55 of my **100 Days of DevOps Challenge by KodeKloud**.

The challenge was related to **Kubernetes Sidecar Containers**. The objective was to create a Pod named `webserver` with an Nginx container and a sidecar container that continuously reads the Nginx access and error logs.

Both containers needed to share an `emptyDir` volume so that the sidecar could access the log files generated by Nginx.

### Challenge Requirement

Create a Kubernetes Pod named `webserver` with the following configuration:

- Create an `emptyDir` volume named `shared-logs`.
- Create the main container named `nginx-container` using `nginx:latest`.
- Create a sidecar named `sidecar-container` using `ubuntu:latest`.
- Mount the shared volume at `/var/log/nginx` in both containers.
- Configure the sidecar to read the access and error logs every 30 seconds.
- Configure the sidecar under `initContainers` with `restartPolicy: Always`.
- Verify that the Pod and its containers are running.

# Solution

## Step 1: Understand the Task

A sidecar container is a supporting container that runs alongside the main application container.

In this challenge:

- Nginx runs the web server.
- The Ubuntu sidecar reads Nginx access and error logs.
- Both containers share a volume named `shared-logs`.

This design allows log processing to happen separately from the main application.

## Step 2: Create the YAML File

I created a Kubernetes manifest named `webserver-pod.yaml`.

```bash
vi webserver-pod.yaml
```

## Step 3: Configure the Pod

I added the following configuration to the file:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: webserver
spec:
  volumes:
    - name: shared-logs
      emptyDir: {}

  initContainers:
    - name: sidecar-container
      image: ubuntu:latest
      restartPolicy: Always
      command:
        - sh
        - -c
        - while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx

  containers:
    - name: nginx-container
      image: nginx:latest
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
```

### Explanation of the Configuration

**1. Pod name**

```yaml
metadata:
  name: webserver
```

Creates a Pod named `webserver`.

**2. Shared volume**

```yaml
volumes:
  - name: shared-logs
    emptyDir: {}
```

Creates an `emptyDir` volume that can be accessed by both containers. Its data is temporary and is removed when the Pod is removed.

**3. Main container**

```yaml
containers:
  - name: nginx-container
    image: nginx:latest
```

Runs the Nginx web server.

**4. Sidecar container**

```yaml
initContainers:
  - name: sidecar-container
    image: ubuntu:latest
    restartPolicy: Always
```

Defines the sidecar using the required Ubuntu image. The `restartPolicy: Always` setting makes this an always-running sidecar-style init container.

**5. Log-reading command**

```bash
while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done
```

This command continuously reads both log files and waits 30 seconds before repeating.

**6. Shared mount path**

```yaml
volumeMounts:
  - name: shared-logs
    mountPath: /var/log/nginx
```

Both containers mount the same volume at the same path so they can access the shared files.

## Step 4: Apply the Configuration

After saving the YAML file, I created the Pod using:

```bash
kubectl apply -f webserver-pod.yaml
```

## Step 5: Verify the Pod

I checked the Pod status:

```bash
kubectl get pods
```

Then I inspected its configuration and events:

```bash
kubectl describe pod webserver
```

The Pod should reach the `Running` state, and both the Nginx and sidecar containers should be running.

## Step 6: Verify Nginx Logs

I checked the main container logs:

```bash
kubectl logs webserver -c nginx-container
```

## Step 7: Verify Sidecar Logs

I checked the sidecar logs:

```bash
kubectl logs webserver -c sidecar-container
```

The sidecar reads the Nginx access and error log files every 30 seconds. If the log files are initially empty, the output may contain no log entries until Nginx generates some.

# Troubleshooting

### Problem 1 - Sidecar Container Not Recognized

If the KodeKloud validator reports that `sidecar-container` does not exist, check whether it was placed under `initContainers` as required by this lab.

### Problem 2 - Incorrect Image

The sidecar must use the exact image:

```yaml
image: ubuntu:latest
```

The main container must use:

```yaml
image: nginx:latest
```

### Problem 3 - Pod Does Not Reach Running State

Inspect the Pod:

```bash
kubectl describe pod webserver
```

Check the container logs:

```bash
kubectl logs webserver -c nginx-container
kubectl logs webserver -c sidecar-container
```

Ensure that the sidecar has:

```yaml
restartPolicy: Always
```

### Problem 4 - Log Files Are Not Shared

Both containers must mount the same volume name at the same path:

```yaml
name: shared-logs
mountPath: /var/log/nginx
```
